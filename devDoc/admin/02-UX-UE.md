# Lumio Admin — UX/UE 设计说明

## 1. 信息架构（导航，10 项，3 组）

```
Lumio Admin
├─ 总览 Overview                      ← 进后台默认页
├─ 内容运营
│   ├─ 素材库 Materials
│   ├─ 分享管理 Shares        (badge 待处理举报数)
│   ├─ 内容安全 Safety        (badge 待复审数)
│   └─ 公告运营 Announcements
├─ 用户与增长
│   ├─ 用户记录 Users
│   └─ 邀请裂变 Invites
└─ 监控与治理
    ├─ 报错监控 Errors        (badge 今日失败数)
    ├─ 成本看板 Cost
    └─ 审计日志 Audit
```

侧栏红点 badge 用于「需要人来处理」的待办（举报/复审/报错），静态数据模块不加 badge。

## 2. 布局骨架

- **左侧栏 236px**：固定深墨蓝 `#16181F`。顶部品牌，中部分组导航，底部当前管理员身份。
- **顶部条 sticky**：页名 + 面包屑（左），全局搜索（右，搜邮箱/任务ID/分享）。半透明毛玻璃。
- **内容区**：统一节奏 —「摘要（KPI 行）→ 筛选条 → 数据表/网格 → 分页」。
- **右侧抽屉 480px**：所有「详情/编辑」走 slide-over 抽屉，不跳页，保留列表上下文。Esc / 点遮罩关闭。

## 3. 视觉 Token

| 类别 | 值 | 用途 |
|------|-----|------|
| ground | `#F6F7F9` | 内容区底 |
| sidebar | `#16181F` | 侧栏 |
| surface | `#FFFFFF` | 卡片/表格 |
| border | `#E6E8EE` | 描边 |
| ink / muted / faint | `#191C24` / `#6A6F7D` / `#969BA8` | 文字三级 |
| **accent 鸢尾蓝** | `#5B61E8` | 激活态、主按钮、关键数据、图表主线。**不使用渐变堆砌** |
| good / warn / crit | `#1E9E63` / `#C9820A` / `#D9484C` | 语义状态（与 accent 独立） |
| 字体 | 系统无衬线栈（含 PingFang/YaHei 中文回退） | 避免 CDN 字体被 CSP 拦截 |
| 数据字体 | 等宽栈 + `tabular-nums` | ID、金额、数字列对齐 |

**状态编码**：一律用 pill（圆点+色）表达状态，让「需关注项」一眼可辨——被举报=红、待发放=黄、正常=绿、中性=灰、强调=蓝。

## 4. 各模块交互要点

| 模块 | 主视图 | 关键交互 |
|------|--------|----------|
| 总览 | KPI×5 + 生图趋势(canvas 面积图) + 模型分布(条形) + 待处理清单 | 待处理项「去处理」直达对应模块 |
| 素材库 | 卡片网格（缩略图/排序号/拖拽柄） | 上传、编辑（抽屉：标题/分类/prompt/换图）、隐藏、删除、拖拽排序 |
| 分享管理 | Tab：分享列表 / 排行榜 | 行→抽屉（大图/prompt/举报记录），下架/恢复/清零举报；被举报置顶红标 |
| 内容安全 | Tab：复审队列 / 违禁词库 | 复审抽屉（高亮命中词，通过/下架/封作者）；违禁词增删改+动作(拦截/标记) |
| 公告运营 | 列表表格 | 新建/编辑公告，位置+生效时间 |
| 用户记录 | 数据表（生图数/成功率/分享/活跃/额度来源） | 搜邮箱，行→详情抽屉（mini-KPI + 生图记录 + 设备风控 + 邀请）。**额度只读，注明由外部支付管** |
| 邀请裂变 | KPI×4 + 邀请关系表 | 状态筛选，作弊拦截红标 |
| 报错监控 | KPI×4(按类型) + 失败任务表 | 类型/模型/时间筛选，行→抽屉。抽屉先显示定位信息（任务ID/**请求ID**/**上游请求ID**/用户ID/上游HTTP状态/code/type）；**上游原始返回体、error_message、params 默认折叠，点「查看」才展开**（重信息不占默认视野）；「查看该用户」跳转 |
| 成本看板 | KPI×4 + 每日成本(canvas) + provider 拆分 + Top 用户 | 时间范围切换。标注「估算值，以账单为准」 |
| 审计日志 | 动作表 | 按动作类型/管理员筛选 |

## 5. 关键 UX 决策

1. **抽屉而非跳页**：详情/编辑全部 slide-over，运营处理待办时不丢列表位置，效率优先。
2. **摘要先行**：每个可操作模块顶部先给 KPI/待办摘要，再给明细表——扫读优先，符合工具型后台。
3. **待办可路由**：总览的待处理项、badge 与列表红标形成「发现→点击→处置」闭环。
4. **额度不可编辑**：用户详情里额度来源只读展示并标注外部管理，避免与支付系统冲突。
5. **危险操作**：下架/删除/封禁用红色描边按钮，落地时需二次确认 + 写审计日志。

## 6. 落地对照（评审通过后）

- 前端：Next.js App Router，`/admin/*` 页面 + 布局组件；建议单独 `src/app/admin/` 目录 + 客户端组件，复用抽屉/表格/pill 等基础件。
- 后端：`/api/admin/*` 全部服务端校验 `email ∈ ADMIN_EMAILS`（见 PRD §2/§6）。
- 图表：canvas 手绘轻量面积/条形图，避免引入图表库依赖。
- 响应式：后台默认桌面优先；<1100px 时侧栏可折叠为图标（本期可暂不做）。
