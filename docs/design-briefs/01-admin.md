# 01 · 管理后台（Admin · 运营面设计补课）

> 前提：先读 [00-unified-shell.md](00-unified-shell.md)。管理后台（`/admin`，`ADMIN_EMAILS` 白名单准入）是产品的**运营面**，服务对象是运营者自己——专业工具用户，要信息密度与效率。现状是工程即兴实现：公共组件雏形已在（Pill/KPI 卡/抽屉/折线图），但写操作反馈缺失、危险操作靠 `window.confirm`、工程枚举直出、四态残缺。本轮目标：**把十个模块升级为有设计权威的运营后台**——不新增后端能力，只重组表达、补齐反馈与状态、统一词表。

## 1. 背景与功能现状（设计前必读盘点）

导航三组十模块（`AdminNav.tsx`，分享/安全/报错三项带待处理红点，计数来自 overview 接口、加载失败不阻塞）：

| 组 | 模块 | 界面现状 | 写操作现状 |
|------|------|------|------|
| — | 总览 | 5 KPI 卡（今日成功/成功率/累计用户+今日新增/今日活跃/待处理三合一）+ 14 天成功失败双线趋势 + 模型用量条形 + 待处理时间线三链接 | 无 |
| 内容运营 | 素材库 | 分类筛选 + 卡片网格（缩略图/标题/分类/排序号），隐藏态仅 opacity .5 | 新建/编辑抽屉（title/category/prompt/imageUrl/sortOrder 手填数字排序）；隐藏/恢复裸 PATCH 无确认；删除 `window.confirm`；成功后整页 reload，无 toast |
| 内容运营 | 分享管理 | 双 Tab：分享列表（状态+时间筛选、表格、详情抽屉：大图/KV/prompt/下架·恢复）+ 乐于分享排行 | 下架 `window.confirm`，失败用 `alert`；已下架内容无法预览；举报理由不可见 |
| 内容运营 | 内容安全 | 双 Tab：复审队列（表格+抽屉：命中词/prompt 原文/判定通过·下架并标记）+ 违禁词库（行内新增表单/搜索/表格） | 复审两按钮点完直接关抽屉**无任何反馈**；违禁词只能删了重加，无编辑 |
| 内容运营 | 公告运营 | 表格 + 编辑抽屉（标题/内容/位置 4 选/状态 3 选/生效起止 datetime） | 无起止时间校验（可起 > 止）；无前台预览；删除 `window.confirm` |
| 用户与增长 | 用户记录 | 邮箱搜索（防抖）+ 三种排序 + 8 列表格 + 分页（20/页）；详情抽屉：3 mini KPI + KV + 最近 10 条生图时间线 + 设备/IP 风控时间线 | 纯只读（禁用/重置额度等能力后端未有） |
| 用户与增长 | 邀请裂变 | 4 KPI（累计/成功奖励+转化率/待发放/作弊拦截）+ 状态筛选 + 6 列表格 | 纯只读；无手动发放/取消 |
| 监控与治理 | 报错监控 | 4 KPI + 错误类型 Tab + 邮箱/模型/时间筛选 + 表格 + 详情抽屉（KV/上游 HTTP 状态卡/三个折叠 JSON 块/「查看该用户」跳转） | 只读；**硬编码 limit 200 无分页且静默截断** |
| 监控与治理 | 成本看板 | 时间范围切换 + 4 KPI（总数/估算成本/单张均价/失败损耗）+ 每日成本折线 + provider 拆分条形 + 成本 Top 用户 | 只读；数据为估算值 |
| 监控与治理 | 审计日志 | 分类 Chip 筛选 + 5 列表格（动作 Pill 按类别配色） | 只读；详情是截断 80 字符的 JSON |

公共底座现状：`ui.tsx`（Pill 五 tone / SectionHead / Kpi / Loading / ErrorState / Empty / useAdminData hook）、`Drawer.tsx`（右滑抽屉，Esc/scrim 可关）、`LineChart.tsx`（Canvas 折线，无悬停）、`format.ts`（timeAgo/fmtDate/fmtNum/pct/truncate）。未授权是整页 403 +「返回生图站」。仅亮色主题（深灰侧栏是既有签名），1080px 以下侧栏简单隐藏。

## 2. 设计系统硬约束（`.ad-*` token 体系）

后台沿自己的 `.ad-*` 体系（与前台 `--studio-*` 分治：后台要表格密度，前台要创作氛围），任何新屏不得引入体系外颜色：

| 类别 | Token | 值 |
|------|-------|-----|
| 地色/侧栏/卡面 | `--ad-ground` / `--ad-sidebar` / `--ad-surface` | `#F6F7F9` / `#16181F` / `#FFFFFF` |
| 强调 | `--ad-accent` / `--ad-accent-ink` / `--ad-accent-soft` | `#5B61E8` / `#3F44C4` / `#EEEFFC` |
| 语义 | `--ad-good` / `--ad-warn` / `--ad-crit`（各配 -soft 底色） | `#1E9E63` / `#C9820A` / `#D9484C` |
| 文字 | `--ad-ink` / `--ad-muted` / `--ad-faint` | `#191C24` / `#6A6F7D` / `#969BA8` |
| 边框/阴影 | `--ad-border` / `--ad-border-strong` / `--ad-shadow` / `--ad-shadow-lg` | `#E6E8EE` / `#D5D8E0` / — |
| 字体 | `--ad-sans` 系统栈 / `--ad-mono`（ID、JSON、哈希一律 mono + `ad-tnum` 表格数字） | — |

风格规则：**深色侧栏 + 浅色工作区是后台身份签名，保留**；与前台的血缘靠 Logo 与 accent 紫色系体现即可，不强行套用前台点阵/橙色标注。**暗色主题本轮范围外**。数据密度优先：14px 基准字号、紧凑行高不动。

## 3. 要设计的屏

### 屏 A · Admin Shell 与公共组件升级（其余各屏地基，先定稿）

- 侧栏三组十项 + 红点徽标规格（计数加载中/失败的表达——现为 best-effort，静默无徽标，设计定稿是否可接受）；顶栏（标题/面包屑/操作区）；未授权 403 页体验化（现为一段话+按钮）。
- **公共组件补全（本任务书最重要交付）**，在现有 Pill/Kpi/Drawer 基础上新增并给全规格：
  - `ConfirmDialog`：产品级确认弹窗，列明影响范围（「下架后分享链接立即失效」），**全面替换 `window.confirm` / `alert`**；
  - `Toast`：成功/失败轻反馈，**全面替换「操作后整页 reload」的哑成功**；操作后列表局部刷新的过渡表达（行淡出/状态原地翻转）；
  - `EmptyState` 三变体：暂无数据 / 收束性（「复审队列为空 🎉」保留升级为正式规格）/ 错误+重试；
  - 表格规格：列对齐、行 hover 与可点暗示、`仅显示最近 N 条`诚实截断条（报错监控 200 条硬上限必须用它，不得静默截断）、统一分页器（用户记录已有分页，样式收编为公共件）；
  - 图表悬停：折线/条形的数据点 tooltip 规格（现 Canvas 图无任何交互）。
- 1080px 以下降级方案：侧栏收为抽屉/底部切换，表格给横向滚动容器（不可崩坏）。

### 屏 B · 总览仪表板

- 现有 5 KPI + 趋势 + 模型分布 + 待处理时间线的层级重排：**待处理项是运营者进门第一眼要看的**，评估是否升为首屏主角（红点三项 → 各自模块深链）。
- 全部数据区四态（现无空态处理）；KPI 卡 delta（今日新增 ▲）的涨跌语义色规格。

### 屏 C · 内容运营四模块

- **素材库**：隐藏态从 opacity .5 升级为明确徽标+置灰规格；手填 sortOrder 数字升级为卡片拖拽排序（后端已有 reorder 接口）；「改动即时对前台生效」的提示保留并升级为正式告知条；图片仅支持 URL 粘贴的现实要给输入校验与预览（直传是后端能力，范围外，不画假上传）。
- **分享管理**：下架/恢复走 ConfirmDialog + Toast；已下架条目给「内容已下架」占位而非空白；举报数 >0 时给举报上下文的位置预留（举报理由后端未存，只标注扩展位，不画假数据）。
- **内容安全**：复审「判定通过/下架并标记」操作后必须有结果反馈 + 队列条目消失过渡（现状点完毫无反应是最严重的哑成功）；「复审结论仅记审计、v1 不改任务状态」的边界在界面上如实标注；违禁词 flag/block 两动作给中文词表（标记复审/直接拦截）与解释。
- **公告运营**：起止时间校验（止 ≥ 起）；状态机表达（草稿→生效中→已结束）与「生效中」的醒目度；**新增前台预览态**——按 00 号屏 A 定稿的公告横幅样式给所见即所得预览（两任务书的联动点）。

### 屏 D · 用户与增长两模块

- **用户记录**：只读定位如实表达（无禁用/重置额度按钮，不画假操作）；额度来源 Pill 中文词表；设备/IP 风控时间线的哈希值用 mono + 截断 + 复制。
- **邀请裂变**：作弊拦截（红）与待发放（黄）的语义色规格；「待发放/无手动发放能力」的诚实表达；转化率 delta 规格。

### 屏 E · 监控与治理三模块

- **报错监控**：错误类型工程枚举全部中文化（见 §4 词表）；上游 JSON 折叠块保留（工程排障需要原文），但折叠块标题与摘要行说人话；「查看该用户」跨模块深链保留并给规格；200 条截断条（屏 A 公共件）。
- **成本看板**：「估算值，以 provider 账单为准」免责声明升级为正式规格；失败损耗为 0 与 >0 的两态表达。
- **审计日志**：截断 JSON 详情升级为「摘要人话 + 点开看原文」两层；动作 Pill 的类别配色表正式登记（share.takedown=crit、material.*=accent、safety.*=warn、announcement.*=good）。

## 4. 全局交互规范（每一屏都要遵守，对齐 00 号 §4）

1. **四态完备**：每个数据区域给 默认/空/加载/错误 四态；错误必带重试；空态区分「暂无数据」与「收束性」（队列清空是好事，庆祝性表达）。
2. **mutation 必有反馈**：所有写操作成功 Toast + 局部刷新，禁止哑成功与整页 reload；失败 Toast 说人话。
3. **破坏性操作必确认**：删除素材/删除违禁词/下架分享/删除公告一律 ConfirmDialog 列明影响，禁用 `window.confirm` / `alert`。
4. **工程枚举中文词表（逐字执行）**：`provider_error`=上游服务报错、`quota_exhausted`=额度耗尽、`rate_limited`=触发限流、`internal_error`=站内错误；`paid`=付费、`invite`=邀请奖励、`login`=登录赠送、`anonymous`=匿名试用；`draft`=草稿、`active`=生效中、`ended`=已结束；`flag`=标记复审、`block`=直接拦截。ID/哈希/JSON 原文允许保留但一律 mono 字体 + 可复制。
5. **禁假 UI**：后端没有的能力（图片直传、批量操作、手动发放奖励、用户禁用、导出、告警阈值）**不画**；确需占位的用「规划中」置灰并在 README 登记。
6. **可达性**：抽屉 Esc 可关（已有，保持）、表格行键盘可达、焦点态齐全。
7. **数据诚实**：任何截断（200 条、Top 6 模型、最近 10 条）必须显式标注数量与去向链接。

## 5. 已锁产品决策（设计不得违反）

- 准入 = `ADMIN_EMAILS` 白名单，无角色分级——本轮不设计权限矩阵。
- 审计日志只读、不可撤销；复审结论 v1 仅记审计不改任务状态；成本永远是估算口径。
- 素材库改动即时对前台生效（无发布/草稿流程），设计按此表达风险提示。
- 本轮**纯前端表达升级**：不新增后端能力（见 §4.5 清单），唯一例外是素材拖拽排序（reorder 接口已存在）。

## 6. 交付格式

- 高保真原型（独立可运行 HTML 或 Figma）+ handoff README（Overview / 逐屏 Layout 与组件 / Interactions & Behavior / 状态清单 / 词表 / 新增组件登记）。
- 公共组件（屏 A）单独成册，十模块引用不重复定义；与现网不一致处 README 写明理由。
