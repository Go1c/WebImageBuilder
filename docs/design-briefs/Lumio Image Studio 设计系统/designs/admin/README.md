# Handoff · 01 管理后台（Admin）

高保真可运行原型：`index.html`（`admin-base.css` + `admin-components.css` + `admin-data.js` + `admin-views.js` + `admin-app.js`）。
`admin-base.css` 逐字沿自现网 `admin.css`（.ad-* token 体系，ground truth）；新增件全部收在 `admin-components.css`（.adx-* 前缀），不污染基础体系。左下「状态演示」条为审阅工具。

## 屏 A · 公共组件（本轮最重要交付，单独成册）

| 组件 | 规格要点 |
|---|---|
| ConfirmDialog `.adx-dialog` | 标题 + 说明 + **影响范围条**（warn 黄 / crit 红两档）+ 取消/确认；crit 档确认钮红底。全面替换 `window.confirm` / `alert`。Esc / scrim 可关。 |
| Toast `.adx-toast` | 右下角深底轻反馈，绿点=成功 / 红点=失败，可带 mono 副文案（ID）；3s 自动消失。全面替换整页 reload 哑成功。 |
| EmptyState ×3 `.adx-empty` | 暂无数据（灰）/ 收束性（绿 🎉，队列清空庆祝）/ 错误+重试（红，文案明确「不是空数据」）。 |
| 诚实截断条 `.adx-truncate-strip` | 表尾虚线条：「仅显示最近 N 条」+ 原因 + 去向链接。报错监控 200 条硬上限必须使用。 |
| 统一分页器 `.adx-pager` | 总数（左）+ 页码（右），收编自用户记录现有分页。 |
| 图表 tooltip `.adx-chart-tip` | SVG 折线悬停：竖向就近吸附数据点，深底 tip 显示日期 + 各系列值；数据点圆点随悬停显隐。 |
| 行过渡 | 操作后行淡出（`.adx-row-leaving`）或原地状态翻转 + Toast，禁止整页刷新。 |
| 403 | 锁形图标 + 白名单说明 + 当前邮箱（mono）+ 返回生图站 / 重新登录。 |
| 1080px 降级 | 侧栏收为抽屉（顶栏 ☰），KPI 2 列，表格横向滚动容器。 |

侧栏红点徽标：计数来自 overview 接口，**加载失败静默隐藏徽标、不阻塞导航（定稿：可接受）**——演示条「徽标加载失败」可查看该态。

## 屏 B · 总览

**待处理三项升为首屏主角**（红色左缘卡 + 大数字 + 各自模块深链，位于 KPI 之上）——运营者进门第一眼是要处理的事，不是曲线。5 KPI 带涨跌语义色（▲绿 ▼红 —灰）；14 天双线趋势与模型条形均有悬停 tooltip；模型条形标注「Top 4 · 共 4 个」诚实截断。

## 屏 C · 内容运营四模块

- **素材库**：隐藏态 = 灰化缩略图 + 「已隐藏 · 前台不可见」深色徽标（替代 opacity .5）；**卡片拖拽排序**（reorder 接口已有），落点即保存 + Toast；「改动即时对前台生效」升级为 warn 告知条；编辑抽屉图片 URL 校验（格式错误红框 + 文案）+ 实时预览，不画假上传。删除/隐藏走 ConfirmDialog。
- **分享管理**：下架/恢复走 ConfirmDialog（影响范围：「下架后分享链接立即失效」）+ Toast；已下架条目详情给「内容已下架」占位而非空白；举报数 >0 显示 warn pill，抽屉内标注「举报理由后端暂未存储，此处为扩展位」。
- **内容安全**：复审「判定通过 / 下架并标记」→ Toast + 行淡出消失 + 徽标计数递减，清空后出**收束性空态 🎉**；「复审结论仅记审计、v1 不改任务状态」以告知条 + 抽屉内文案如实标注；违禁词 flag/block 中文词表（标记复审 / 直接拦截）+ 行内解释；删除词走 ConfirmDialog（「历史命中统计保留」）。
- **公告运营**：起止时间校验（止 ≤ 起时红框 + 报错 + 阻止保存）；状态机条（草稿→生效中→已结束，当前态绿色）；**前台预览** = 00 号屏 A 公告横幅的浅色态所见即所得，内容输入实时同步（两任务书联动点）。

## 屏 D · 用户与增长

- **用户记录**：只读定位以告知条如实表达（无禁用/重置按钮）；额度来源中文 pill（付费/邀请奖励/登录赠送/匿名试用）；设备指纹与 IP mono + 截断 + 复制按钮；详情抽屉 = 3 mini KPI + KV + 生成时间线 + 风控区。
- **邀请裂变**：待发放 = warn 黄、作弊拦截 = crit 红；待发放卡注明「按账户中心批次发放，无手动发放能力」；转化率 delta 绿色 ▲。

## 屏 E · 监控与治理

- **报错监控**：类型枚举全部中文化（词表见下），表格 pill 中文 + 抽屉内保留 mono 原文；上游 JSON 三折叠块保留（标题说人话：上游响应原文/请求参数/站内上下文）；HTTP 状态卡；「查看该用户」跨模块深链；表尾 200 条诚实截断条。
- **成本看板**：「估算值，以 provider 账单为准」升级为告知条；失败损耗 >0 为 warn 黄数字（=0 时绿色对勾态，卡内已注）。
- **审计日志**：列表 = 摘要人话，点开抽屉看原始 JSON（默认展开）；动作 Pill 配色表登记：`share.takedown`=crit、`material.*`=accent、`safety.*`=warn、`announcement.*`=good。

## 词表（逐字执行）

`provider_error`=上游服务报错 · `quota_exhausted`=额度耗尽 · `rate_limited`=触发限流 · `internal_error`=站内错误 · `paid`=付费 · `invite`=邀请奖励 · `login`=登录赠送 · `anonymous`=匿名试用 · `draft`=草稿 · `active`=生效中 · `ended`=已结束 · `flag`=标记复审 · `block`=直接拦截。ID/哈希/JSON 一律 `--ad-mono` + 可复制。

## 未画的能力（后端没有，登记为规划中）

图片直传、批量操作、手动发放/取消邀请奖励、用户禁用/重置额度、导出、告警阈值、审计日志时间范围导出（截断条中以「规划中」注明）。

## 与现网不一致处（理由）

1. 总览待处理三项升为首屏主角——运营优先级重排（§屏 B）。
2. 全部 `window.confirm`/`alert`/整页 reload 移除——§4.2/4.3 硬性要求。
3. 素材 sortOrder 手填数字改拖拽——reorder 接口已存在，唯一允许的能力升级。
4. 表单字段从复用 `.ad-btn` 改为独立 `.ad-field`——输入框与按钮共用盒样式导致 hover/焦点语义混乱。
